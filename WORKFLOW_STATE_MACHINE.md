# 🔄 آلة الحالات لدورة حياة الطلب (RFQ & Order State Machine)

لتجنب حدوث تعارض البيانات (Race Conditions) أو التلاعب بالأرصدة المالية، يعتمد النظام على نمط **State Pattern** الصارم. لا يمكن انتقال الطلب من حالة إلى حالة أخرى إلا بعقد مالي وإداري مكتمل.

---

## 1. مخطط الحالات المعتمد (State Flow Diagram)

```
[1. DRAFT] ──► [2. PUBLISHED] ──► [3. RECEIVING_OFFERS]
                                          │
                                          ▼
[6. PREPARING] ◄── [5. ESCROW_LOCKED] ◄── [4. OFFER_ACCEPTED]
       │
       ▼
[7. READY_FOR_PICKUP] ──► [8. DISPATCHED] ──► [9. DELIVERED]
                                                     │
                                                     ▼
                                          [10. ESCROW_HOLD_15_DAYS]
                                                     │
                             ┌───────────────────────┴───────────────────────┐
                             ▼                                               ▼
                    [11. NO_DISPUTE]                                [12. DISPUTE_OPENED]
                             │                                               │
                             ▼                                               ▼
                    [13. ESCROW_RELEASED]                           [14. DISPUTE_RESOLVED]
                             │                                               │
                             └───────────────────────┬───────────────────────┘
                                                     ▼
                                            [15. INVOICE_ZATCA_ISSUED]
                                                     │
                                                     ▼
                                            [16. RATED & COMPLETED]
```

## 2. جدول شرح الحالات والشروط المسبقة (States & Transitions)

| # | اسم الحالة (State Code) | الوصف | الشرط المسبق للتحول (Pre-condition) | الإجراء المالي / النظامي المتخذ |
|---|---|---|---|---|
| **1** | `RFQ_DRAFT` | مسودة الطلب لدى العميل | إدخال بيانات السيارات والقطع | لم يتم خصم شيء |
| **2** | `RFQ_PUBLISHED` | نشر الطلب وتوزيعه | اكتمال بيانات الطلب والتأكيد | إشعارات للموردين المتوافقين |
| **3** | `OFFERS_IN_PROGRESS` | استقبال عروض الأسعار | وجود موردين نشطين | تسجيل عروض أسعار تنافسية |
| **4** | `OFFER_ACCEPTED` | اعتماد العميل لعرض محدد | اختيار العميل لعرض | قفل العرض وتجميد باقي العروض |
| **5** | `SUPPLIER_CONFIRMED` | تأكيد المورد للتوفر الفعلي | فحص المستودع من المورد | التأكُّد قبل الخصم المالي |
| **6** | `FUNDS_LOCKED_ESCROW` | خصم وحجز المبلغ | توفر رصيد متاح في محفظة العميل | خصم من الرصيد المتاح -> نقل للرصيد المحجوز |
| **7** | `ORDER_PREPARING` | المورد يجهز الشحنة | نجاح عملية الحجز المالي | إشعار لمناديب التوصيل القريبين |
| **8** | `COURIER_ASSIGNED` | قبول مندوب التوصيل للطلب | موافقة المندوب عبر التطبيق | ربط المندوب بالطلب وتحديث الخريطة |
| **9** | `IN_TRANSIT` | الشحنة في الطريق للعميل | استلام المندوب للقطع من المورد | تشغيل التتبع المباشر GPS |
| **10** | `DELIVERED_SUCCESS` | تسليم الشحنة للعميل | التوقيع الإلكتروني وصورة الإثبات | بدء عداد الـ 15 يوماً التلقائي |
| **11** | `ESCROW_HOLDING` | فترة الحجز والضمان (15 يوم) | مرور الأيام دون اعتراض | حماية حقوق العميل والمورد |
| **12** | `DISPUTE_RAISED` | فتح طلب استرجاع/نزاع | تقديم العميل لطلب مبرر | إيقاف العداد التلقائي وإشعارات للإدارة |
| **13** | `FUNDS_RELEASED` | تحويل الرصيد للمورد | انتهاء الـ 15 يوماً أو تسوية النزاع | نقل من الرصيد المحجوز -> محفظة المورد المتاحة |
| **14** | `ZATCA_INVOICE_SENT` | إصدار وتوثيق الفاتورة | اكتمال المعاملة بنجاح | إرسال الفاتورة لهيئة ZATCA وأرشفتها |
| **15** | `COMPLETED` | إغلاق الطلب نهائياً | التقييم المتبادل | إضافة التقييم لسجل المورد والعميل والمندوب |
