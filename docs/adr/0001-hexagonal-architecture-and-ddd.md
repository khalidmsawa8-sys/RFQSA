# 📄 ADR 0001: اعتماد معمارية الأشكال السداسية والتصميم الموجه بالدومين (Hexagonal Architecture & DDD)

* **التاريخ:** 25 يوليو 2026
* **الحالة:** مقبول (Accepted)
* **السياق والمشكلة:**
نحتاج إلى بناء منصة B2B متكاملة لإدارة المشتريات والمناقصات (RFQ Marketplace) تتحمل توسعاً كبيراً وأحملاً تتجاوز 30,000 مستخدم متزامن، مع ضمان سلامة المعاملات المالية، والقدرة على استبدال أو تحديث أطر العمل (Frameworks) أو قواعد البيانات أو المزودين الخارجيين مستقبلاً دون الحاجة لإعادة كتابة منطق الأعمال (Domain Logic).

* **القرار المعماري:**
تم اتخاذ القرار باعتماد **Hexagonal Architecture (Ports & Adapters)** مجتمعة مع **Domain-Driven Design (DDD)**:
1. طبقة الأعمال (Domain Layer) مستقلة 100% ولا تعتمد على NestJS أو TypeORM/Prisma أو أي مكتبة خارجية.
2. التواصل مع الخارج يمر حصرياً عبر **Ports (Interfaces)** و **Adapters (Implementations)**.
3. التبعيات تُحقن عبر الـ Dependency Injection باستخدام العقود (Contracts/Interfaces).

* **الآثار والنتائج (Consequences):**
* **الإيجابيات:**
  * سهولة إجراء الفحوصات والـ Unit Tests دون الحاجة لـ Mocks معقدة أو تشغيل قواعد بيانات.
  * مرونة كاملة لتبديل مزودي الخرائط، الرسائل، أو بوابات الدفع.
  * عزل تام وأمان مرتفع للكود المالي وإدارة المناقصات.
* **السلبيات / التحديات:**
  * زيادة طفيفة في عدد الملفات والـ Interfaces في مرحلة التأسيس الأولى، ولكنها تضمن سرعة واستقرار ممتد لسنوات.
